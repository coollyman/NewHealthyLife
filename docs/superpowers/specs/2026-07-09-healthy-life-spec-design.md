# 健康生活功能与 UI 重实现 SPEC

## 1. 目标

从零重新实现一个 HarmonyOS「健康生活」习惯打卡应用。新应用以华为官方 Codelab 页面展示的功能和 UI 为主要依据：用户可以启用最多 6 个预设健康任务，设置每日目标，每天打卡，查看进度，获得连续打卡成就，并使用服务卡片。

旧项目代码不作为实现依据，只作为资源池使用。可以复用或复制旧项目中的图片、图标、动效资源、文案资源和截图参考；不要复制旧代码的架构、生命周期假设、持久化耦合方式或已知/潜在 bug。

## 2. 重实现方向

### 已选方向：功能/UI 对齐，内部全新实现

根据官网 Codelab 重建可见功能和 UI 流程，但内部实现要重新设计。保留任务目录、主要页面、打卡交互、进度展示、成就徽章、提醒和服务卡片；用更简单、可测试的领域模型和明确的状态转换实现。

这不是源码级复刻。如果旧代码行为、官网展示和用户预期冲突，优先级为：用户要求 > 官方 Codelab 展示/说明 > 本 SPEC > 旧项目代码。

如果第一轮完整复刻范围过大，可以先实现首页、任务管理、打卡、进度、历史和成就 UI；核心流程稳定后再加入提醒和服务卡片。

推荐执行顺序：先实现领域/数据规则，再接 UI 页面，最后接服务卡片和提醒。

## 4. 主要用户流程

### 首次启动

1. 应用初始化数据库和必要表。
2. 应用确保 6 个默认任务记录存在。
3. 应用初始化成就和连续打卡相关偏好。
4. 应用进入启动流程，然后进入健康生活主页。

### 启用任务

1. 用户从首页进入任务列表。
2. 用户选择一个预设任务。
3. 用户打开任务开关。
4. 如果该任务支持目标配置，用户可以更新目标。
5. 应用持久化任务状态，并创建当天的任务快照记录。
6. 应用重新计算当天目标任务数和已完成任务数。
7. 如果任务是时间类任务，应用请求通知权限并创建或更新提醒。

### 停用任务

1. 用户关闭已启用任务的开关。
2. 应用持久化任务为停用状态。
3. 如果当天存在该任务记录且尚未完成，从当天任务列表中移除。
4. 应用重新计算当天进度。
5. 如果该任务存在有效提醒，取消提醒。

### 每日打卡

1. 用户点击当天任务列表中的某个任务。
2. 应用打开该任务对应的打卡弹窗。
3. 如果任务尚未完成，应用推进打卡进度：
   - 一次性任务直接完成。
   - 增量任务增加对应 step 值。
4. 应用更新当天任务记录的完成状态。
5. 应用重新计算当天进度。
6. 如果所有启用任务当天首次全部完成，应用更新连续天数和成就状态。

### 查看历史

1. 首页展示 21 天窗口：上一周、当前周、下一周。
2. 用户可以选择某一天。
3. 应用展示该日期的进度和任务记录。
4. 未来日期如果缺少任务记录，可以基于当前启用任务生成预览记录。

## 6. 概念数据模型

以下是重实现时的概念实体，命名可以调整。需要保留语义，不要求沿用旧表名或旧字段名。

### TaskInfo

表示每个预设任务的全局配置。新实现中应尽量避免把“当天完成状态”存到全局任务配置里；每日进度更适合放在当天任务记录中。

- `taskId`：数字主键，范围 0-5。
- `isOpen`：任务是否启用。
- `targetValue`：目标时间或数值目标。
- `finValue`：旧模型中的当天完成值；新实现建议放到每日任务记录。
- `isDone`：旧模型中的当天完成标记；新实现建议放到每日任务记录。
- `isAlert`：预留提醒开关。
- `alertStartTime`、`alertEndTime`、`alertFrequency`：预留提醒字段。
- `reminderId`：平台提醒 ID；不存在时为 `-1`。

### DayInfo

表示某一天的聚合进度。

- `date`：主键，格式为 `yyyyMMdd`。
- `targetTaskNum`：该日启用任务数。
- `finTaskNum`：该日已完成任务数。
- `percentage`：派生值，`ceil(finTaskNum / targetTaskNum * 100)`；无任务时为 `0`。

### DayTaskInfo

表示某一天的单个任务快照。

- `id`：自增主键。
- `date`：日期，格式为 `yyyyMMdd`。
- `taskId`：任务目录 ID。
- `targetValue`：创建或更新记录时从任务配置复制的目标值。
- `finValue`：该日该任务的进度值。
- `isDone`：该日该任务是否完成。

### FormInfo

记录已安装的服务卡片。

- `formId`：平台卡片 ID。
- `formName`：`agency` 或 `progress`。
- `formDimension`：卡片尺寸编码。

### Preferences

- `maxConsecutiveDays`：历史最高连续完成天数。
- `currentConsecutiveDays`：当前连续完成天数。
- `currentDayStatus`：今天是否已经计入连续天数。

## 7. 业务规则

当旧代码行为和本 SPEC 冲突时，以本 SPEC 为准；当 SPEC 与官方展示冲突时，以官方展示为准。重实现应避免通过隐藏的全局任务状态去影响历史日期。

### 日期初始化

- 应用启动时创建缺失的数据表。
- 确保 6 个默认任务配置存在。
- 如果当天 `DayInfo` 不存在：
  - 初始化当天聚合记录。
  - 为所有当前启用任务创建当天任务快照。
  - 重新计算当天聚合进度。
  - 不要依赖全局任务记录作为历史完成状态。
- 如果当天 `DayInfo` 已存在：
  - 确保每个启用任务都有匹配的当天任务快照。

### 打卡规则

- 停用任务不能打卡。
- 已完成任务不能重复打卡。
- 一次性任务和时间类任务：设置 `finValue=targetValue`，并标记 `isDone=true`。
- 数值任务：每次打卡增加对应 `step`，当 `finValue >= targetValue` 时标记完成。
- 每次打卡后同步：
  - 对应每日任务记录；
  - 对应每日聚合记录；
  - 服务卡片数据。

### 连续天数与成就规则

- 当 `finTaskNum == targetTaskNum` 时，该日计入连续天数。
- 同一天不能重复增加连续天数。
- 新的一天初始化时，如果前一天存在且未全部完成，将 `currentConsecutiveDays` 重置为 `0`。
- 当前连续天数超过历史最高值时，更新 `maxConsecutiveDays`。
- 当历史最高连续天数首次达到以下阈值时展示成就动画：`3, 7, 30, 50, 73, 99`。

### 提醒规则

- 只有时间类任务需要提醒能力：早起和早睡。
- 启用可提醒任务时：
  - 如有必要，请求通知权限。
  - 创建每天重复的闹钟提醒。
  - 保存平台返回的 `reminderId`。
- 修改已启用时间类任务的目标时间时，更新对应提醒。
- 停用时间类任务时，如果 `reminderId != -1`，取消提醒。

### 服务卡片规则

- 添加卡片时保存 `formId`、`formName`、`formDimension`。
- 删除卡片时移除对应 `FormInfo`。
- 任务状态或进度变化时，更新所有已保存卡片。
- 1x2 `agency` 卡片展示当天任务列表。
- 2x2 `progress` 卡片展示 `targetTaskNum`、`finTaskNum` 和进度百分比。
- 点击卡片拉起应用主页。

## 8. UI 要求

### 启动与入口

- 为了 UI 对齐，可以保留用户可见的启动页、广告页、隐私弹窗流程；内部实现可以简化。
- 主应用使用底部导航。

### 首页

- 展示当日进度摘要。
- 展示三周日期条，并支持日期选中。
- 展示选中日期的任务列表。
- 提供添加/编辑任务入口。
- 选中日期没有任务时展示空状态。
- UI 以官方 Codelab 展示为主，本地 `screenshots/` 作为补充参考：整体应健康、轻量、卡片化，首页优先展示进度、日期和任务。

### 任务管理

- 添加任务页展示 6 个预设任务。
- 每一行展示任务图标、任务名称、已开启状态和进入编辑的指示。
- 编辑任务页包含：
  - 启用/停用开关；
  - 目标设置行；
  - 完成/保存按钮。
- 目标设置方式：
  - 早起、早睡使用 `TimePicker`。
  - 喝水、吃苹果使用 `TextPicker`。
  - 固定一次性任务不提供选择器。
- 编辑页需要清晰区分“启用状态”和“目标设置”，避免旧实现中状态保存与页面返回强耦合。

### 成就

- 成就徽章有已解锁和未解锁两种视觉状态。
- 达到阈值时立即展示成就弹窗或动画。
- 成就页和成就弹窗以官方截图为主，本地徽章资源可直接复用；动画实现可以重新设计。

### 我的/Profile

- 展示静态用户信息。
- 展示个人资料、检查更新等菜单项。

### 服务卡片 UI

- 1x2 卡片展示今日已添加任务，适合快速查看任务列表。
- 2x2 卡片展示今日完成进度，适合快速查看目标任务数、完成任务数和百分比。
- 卡片点击后拉起应用主页。
- 官方说明中提到卡片更新时间到达后会重置第二天任务，且需要重新添加卡片；新实现需要明确这个行为是否保留，默认按官方功能保留。

## 9. 架构建议

建议分层：

- `domain`：任务目录、连续天数规则、打卡规则、日期计算。
- `data`：RDB 仓储和偏好存储仓储。
- `app services`：提醒服务和服务卡片更新服务。
- `ui state`：首页状态、成就状态、导航状态。
- `ui`：页面、组件、弹窗、服务卡片。

不要把业务规则直接写在 UI 组件里。打卡、启用/停用任务、日期初始化、连续天数计算都应能被单独调用和测试。

实现护栏：

- 不要整文件复制旧项目代码。
- 可以复制旧项目资源文件，但需要按新工程资源结构重新归类。
- 不要复用旧的“通过全局任务记录保存当天完成状态”的数据库写法作为主数据源。
- 日期格式化和跨天逻辑必须集中管理。
- 服务卡片和提醒 API 应封装在小服务后面，核心习惯逻辑不能依赖 HarmonyOS 运行时才能测试。
- 官网 Codelab 文本和图片是功能/UI 主参考；本地截图是辅助参考；组件应按一致风格重新实现。
- 不要照抄教程或旧项目的代码结构。

## 10. 验收标准

- 全新安装后生成 6 个默认关闭的任务配置。
- 启用任务会创建当天任务快照，并更新当天目标任务数。
- 停用未完成任务会从当天任务数中移除。
- 一次性任务点击一次即可完成。
- 喝水每次增加 `0.5`，直到达到目标。
- 吃苹果每次增加 `1`，直到达到目标。
- 当天所有启用任务完成后，连续天数只增加一次。
- 新的一天打开应用时，如果昨天未完成全部任务，当前连续天数重置为 `0`。
- 成就在历史最高连续天数达到 `3, 7, 30, 50, 73, 99` 时解锁。
- 任务启用/停用和打卡后，服务卡片数据会更新。
- 时间类任务的提醒可以创建、更新、取消，并与任务状态一致。
- 官方 Codelab 中列出的主要功能全部能在新应用中完成。
- 项目可以通过 DevEco/Hvigor 同步和构建。
- 核心领域规则具备可运行测试或清晰的手动验证步骤。
